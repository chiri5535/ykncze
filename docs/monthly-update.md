# 月次占いの更新手順

このアプリの月次更新は、公開前に運営者が占い内容を確認する。
新しい月を頼まれたら、まずこのリポジトリの最新状態と公開サイトを確認する。

## 毎月の制作

1. 公開中の月と `main` の内容を照合する。違う場合は原因を調べる。
2. `data/archive/` と GitHub 履歴から、直近2〜3か月の本文、アドバイス、アイテム、点数、カラーを読む。未確認の過去データは補わない。
3. その月の天体の動きを信頼できる暦で確認する。日時などの事実と占星術的な解釈を区別し、運営者用の「星の動きメモ」をチャットで渡す。このメモは公開サイトに載せない。
4. 12星座の原稿を既存の順番で作る。読みやすく、明るく、具体的にし、不安を煽る断定は避ける。本文は「○月の○○座は、」から始め、80〜100文字程度を目安にする。アドバイスには「。」を付け、アイテムには付けない。点数は原則3〜5。
5. 過去月と同じ星座のテーマや言い回し、アイテム、カラーを見比べる。同じ月のアイテムとカラーも重複させない。
6. 全文と、テーマ・点数・アドバイス・アイテム・カラーの一覧を運営者に見せる。明確な承認を得るまでコードと公開サイトを変更しない。

## 承認後

1. `src/utils/fortune.js` の占いデータ、`src/utils/zodiac.js` の `lucky`、`src/components/FortuneResult.jsx` の月表示を更新する。星座判定、画像 URL、`getFortune` の export は維持する。
2. 確定データを `data/archive/YYYY-MM.json` に保存する。JSON には `period` と、12星座の `text`、`score`、`advice`、`luckyItem`、`lucky` を入れる。
3. `npm run check:fortune -- YYYY-MM` と `npm run build` を実行する。結果画面を全12星座で確認し、スマートフォン幅も確認する。
4. 変更ファイルと内容を運営者に伝え、月が分かるメッセージで `main` にコミットしてプッシュする。生成された `dist` はコミット対象に含めない。
5. Netlify の公開ページで新しい月の見出し、本文、アイテム、カラーが反映されたことを確認する。一致しない場合は更新完了と報告しない。

次月以降も、運営者は「来月分を作って」と伝えるだけで、この順番で進める。
